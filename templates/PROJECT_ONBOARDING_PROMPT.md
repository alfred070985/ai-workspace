# 新项目接入指令模板

把下面整段发给当前项目里的代理。先替换 `<PROJECT_HINT>`；没有把握时可以让代理根据项目内容提出项目 ID，但必须经你确认。

```text
请把当前目录改造成“跨设备、跨应用可续作项目”。项目提示：<PROJECT_HINT>

1. 检查当前 Git 根目录、远程地址和未提交改动；如果项目身份不明确，先问我。
2. 为当前项目确定一个稳定、简短、唯一的英文 project_id，不要与其他项目重复；建议后等我确认。
3. 创建或完善以下文件：
   - START_HERE.md：新环境入口，保持极短，只说明读取顺序和当前下一步；
   - AGENTS.md：项目边界、禁止事项、常用命令、验收标准和交接规则；
   - .ai/project.yaml：project_id、项目名称、远程仓库地址、入口文件、外部技能或能力依赖；
   - .ai/state.md：当前目标、关键已完成项、唯一下一步、阻塞和真实验证结果；
   - .ai/decisions/：保存长期业务或技术决策。
4. 不要复制其他项目的业务规则、查询脚本、数据文件或绝对路径；只借鉴跨环境续作结构。
5. 检查 .gitignore，排除 .env、config.local.yaml、凭据、本机绝对路径配置、依赖目录和构建产物。
6. 如果项目有大型 Excel、JSONL、二进制模型或数据文件，规划 Git LFS，不要把大文件直接放进普通 Git 历史。
7. 分析当前项目资料，恢复真实当前目标和下一步；资料不足时问我，不要编造。
8. 给我一条应加入 ai-workspace/registry.yaml 的项目登记记录，格式包含 project_id、repo、default_branch、entry。
9. 在我确认远程仓库地址之前，不要擅自创建远程仓库、提交或推送。
10. 我确认空私有仓库后，再初始化或核对 Git、提交并推送；完成后生成一份新的 CONTINUE_PROMPT.md，供其他设备或其他代理继续工作。
```
